# 方案设计：kid-wechat-guard（守护微信内小程序/视频号）

- 版本：v1
- 日期：2026-09-06
- 状态：需求已确认，待开工实现 P1

---

## 1. 背景与问题

孩子使用家里荣耀手机（MagicOS 9.0 / Android 15）。家长已通过以下手段做了系统级防沉迷：

- **荣耀智慧空间**：远程设置应用限额、禁止指定应用、禁止"系统设置"（从而封死孩子手动关无障碍/强停 App/卸载的入口）；
- 微信"隐藏视频号入口"等常规手段。

**发现的唯一绕过点**：微信是单一 App，系统级限额只能"整体限制微信"（会连带锁掉聊天，不可接受），因此**无法限制微信内部的小程序、小游戏、视频号**。孩子通过小程序即可绕开全部限制。

> 已实测确认：目前只有小程序这一条绕过路径，其余手段有效。

## 2. 目标与非目标

### 目标（P1，本机、不联网）
1. 检测微信是否正停在内层容器：小程序/小游戏、视频号。
2. 小程序/小游戏按"每日配额"计时；配额用尽后进入可配置的缓冲期，缓冲结束锁定。
3. **每个内层类别（小程序/小游戏、视频号）都支持两种策略：`禁止`（进入即拦）或 `时长限额`（每日配额）**，可在配置中切换。
4. 锁定/解锁由本机家长密码控制；App 自身启动与配置页均需密码。
5. 记录每日用量，本地可查看。

### 非目标（明确不做）
- 不读取聊天内容、不读小程序标题、不截图、不采集行为（隐私边界：只判断"停在哪类容器 + 用了多久"）。
- 不做系统级应用限制（交给荣耀智慧空间）。
- P1 不做远程审批、不做跨品牌适配。
- 不追求对抗"恢复出厂设置/刷机"等物理级破坏（不可防，交现场大人）。

## 3. 总体架构：两层分工

```
┌─────────────────────────────────────────────┐
│ 系统层（荣耀智慧空间，已有）                     │
│   · 应用限额/禁用（抖音、快手、游戏 App）        │
│   · 禁止"系统设置" → 封死 关无障碍/强停/卸载 入口 │
│   · 应用安装验证                               │
└─────────────────────────────────────────────┘
                 ↓ 微信内部是盲区
┌─────────────────────────────────────────────┐
│ 微信内层（本 App，待开发）                      │
│   无障碍服务：识别 小程序/小游戏/视频号 前台状态   │
│   每类策略：禁止 或 时长限额 + 缓冲 + 锁定页      │
│   家长密码保护配置                              │
└─────────────────────────────────────────────┘
```

系统层与本 App 各自闭环，互不依赖。

## 4. 核心机制设计

### 4.1 检测（无障碍服务 AccessibilityService）
- 监听前台状态变化（包名 + Activity 类名），每 1~2 秒采样一次。
- 判定规则（类名**待真机校准**，微信改版可能变化，见 §7）：
  - 微信前台：包名 `com.tencent.mm`
  - 小程序/小游戏：类名含 `appbrand`
  - 视频号：类名含 `finder`
  - 普通聊天 / 微信主页（`LauncherUI`）：正常，不计时
- 小程序（WebView 渲染）与小游戏（Canvas 渲染）的无障碍特征不同，理论上可区分；P1 不依赖此区分，统一计入小程序/小游戏配额。
- 退出内层容器回聊天 → 计时停止。

### 4.2 策略与拦截
- 每个内层类别（小程序/小游戏、视频号）独立配置策略：
  - `禁止`：进入该容器即拦截，不给时长；
  - `时长限额`：按每日配额计时（支持 学习日/周末 两档）。
- 默认值：
  - 视频号 → `禁止`；
  - 小程序/小游戏 → `时长限额`（学习日 30 分钟 / 周末 60 分钟）。
- 拦截形态：
  - 配额耗尽 → 弹全屏提示 → **可配置缓冲倒计时**（默认 5 分钟，可设 0）→ 缓冲结束进入锁定页；
  - 锁定页两按钮：`返回微信聊天`（通过无障碍 `GLOBAL_ACTION_BACK` 代按返回键退出内层）/ `家长密码解锁`。

### 4.3 配置与授权
- App 启动、设置页、解锁均需家长密码（P1 为本机密码；接口为远程审批预留，见 §6）。
- 首次部署引导：开启无障碍 → 放行自启动 → 忽略电池优化 → **立即设置家长密码**（若孩子抢先在未设密状态下进入设置页设了密码，家长会被反向锁死）。
- 密码错误次数上限 + 延迟（防孩子试密码）。

### 4.4 用量记录
- 本地持久化每日/每类使用时长、拦截次数，简单统计页展示。

## 5. 防绕过与信任模型

| 绕过尝试 | 应对 | 承担方 |
|---|---|---|
| 打开本 App 改配额/关功能 | 配置页密码锁 | 本 App |
| 重启手机 | 开机自启（广播 + 无障碍自恢复） | 本 App + 首次放行自启动 |
| 关闭无障碍 / 强制停止 / 卸载 | 荣耀智慧空间禁止"系统设置"封死入口 | 智慧空间 |
| 恢复出厂 / 刷机 | 不可软件防御，现场大人兜底 | 物理世界 |

结论：在"智慧空间禁掉系统设置"成立的前提下，本地防线基本闭环；本 App 只需保证（a）自身配置密码不可改，（b）开机自启恢复，（c）检测逻辑可靠。

## 6. 远程审批（P2，本期不做，仅预留）

- 能力：锁定页出现"远程请求"→ 父母手机 App 审批 → 限时放行；守护失联（无障碍被关/进程被杀）→ 父母端告警。
- 组件：双端 App + 中继通道（自建 MQTT/VPS 或 NAS）+ 配对加密 + 推送唤醒。
- 预估工作量：约 1.5~2 周 + 常年维护一台中继。
- 现状决定：**先本地跑通、验证真实拦截效果**，再评估是否值得投入。

## 8. 技术栈（建议，待实现前最终确认）

- 语言：**Kotlin**（原生安卓；无障碍/前台服务/系统集成强依赖原生能力）
- 构建：Gradle + Android Studio；`minSdk ≥ 29`，`targetSdk 35`（Android 15）
- 关键组件：`AccessibilityService`、前台服务（`specialUse` 类型）、`DataStore` 本地配置；P1 无网络依赖
- 单 APK，包名待定；工程将置于本目录 `android/` 子目录

## 9. 里程碑

- **P1 本机原型（本期）**：检测 + 策略（禁止/限额）+ 缓冲 + 锁定页 + 密码 + 统计 + 类名校准日志
- P2（可选）：远程审批、失联告警
- P3（可选）：开源加固、白名单（读小程序标题，依赖 R1 数据）

## 10. 默认参数汇总（均可配置）

| 参数 | 默认值 |
|---|---|
| 学习日小程序/小游戏配额 | 30 分钟 |
| 周末小程序/小游戏配额 | 60 分钟 |
| 视频号策略 | 禁止（可切换为限额） |
| 视频号限额（若启用限额） | 学习日 15 分钟 / 周末 30 分钟（待定） |
| 缓冲时长 | 5 分钟（可设 0） |
| 锁定页放行 | 家长密码（本机） |
